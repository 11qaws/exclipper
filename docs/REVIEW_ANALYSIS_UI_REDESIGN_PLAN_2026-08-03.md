# ExClipper 분석·근거 검토 UI 재설계안

작성일: 2026-08-03
대상: `ReviewSurface`, 저장된 사전분석 결과의 검토 화면
상태: 구현 전 승인안

## 1. 확인된 원인

### 화면 크기

- `.rvw`가 `max-width: 1280px`, `height: min(74vh, 720px)`로 잠겨 있다.
- 실제 라이브 하네스 측정:
  - 1280×720: 작업면 1201×600, 문서 높이 784px로 세로 스크롤 발생
  - 1920×1080: 작업면 1280×720
  - 2560×1440: 작업면 1280×720
- 따라서 1080p와 1440p에서 화면이 넓어져도 영상은 672×509, 설명 열은 486px에 머물고 주변만 비게 된다.

### 요약 문구

저장된 사전분석 결과는 현재 한 `why` 필드에 다음 네 내용을 줄바꿈으로 합친다.

1. 발생한 사건
2. 스트리머 반응
3. 클립 추천 이유
4. 빠른 탐색 오버레이의 추천 근거

역할이 다른 문장이 하나의 무제목 문단이 되어 핵심을 찾기 어렵다. 또한 일반 분석 결과에서는 `reactionSummaryKo`를 실제 대사처럼 표시하는 잘못된 매핑도 있다.

### 앞뒤 맥락

저장된 사전분석 결과의 `context`에는 앞 맥락, 주제 맥락, 전체 흐름 판정, 빠른 탐색 근거, 등장인물 설명, 뒤 맥락, 채팅 반응, 인물 근거, 불확실성까지 한 목록으로 들어간다. 요약 화면은 이 전부를 `연관 맥락`으로 노출하므로 편집 결정보다 파이프라인 보고서에 가깝다.

### 근거 탭 플레이어

- 근거 탭을 여는 것만으로는 플레이어가 보이지 않는다. 근거 조각을 눌러야 340px 고정 크기의 떠다니는 카드가 열린다.
- 후보 전환 때 내부 카드 좌표는 지우지만 부모의 `playerCardOpen=true`는 남는다.
- 이후 다른 후보의 근거를 눌러도 “이미 열림” 분기가 실행되어 플레이어 카드를 다시 만들지 못한다. 라이브 하네스에서 그대로 재현했다.

## 2. 편집 작업 정의

### 주 작업

현재 후보를 짧게 재생하고, **무슨 사건인지·스트리머가 어떻게 반응했는지·왜 클립 가치가 있는지**를 확인한 뒤 `사용` 또는 `빼기`를 결정한다.

### 보조 작업

- 실제 대사와 대표 화면으로 AI 설명을 검증한다.
- 앞뒤 맥락이 없으면 이해할 수 없는 후보인지 확인한다.
- 등장인물과 불확실성을 필요할 때만 확인한다.
- 시작·끝을 5초 단위로 다듬는다.

## 3. 정보 계약

### 항상 표시

| 편집자 질문 | 표시할 데이터 | 표시 규칙 |
|---|---|---|
| 무슨 일이 있었나? | `eventSummaryKo` | 관찰된 사건 1~2문장, 최대 110자 |
| 어떻게 반응했나? | `reactionSummaryKo` | 스트리머의 표정·행동·말투 변화 1문장, 최대 80자 |
| 왜 클립인가? | `whyGoodClipKo` | 전개와 보상이 무엇인지 1문장, 최대 80자 |
| 실제로 뭐라고 했나? | 반응 정점에 가장 가까운 확인 대사 | 실제 cue만 사용, 없으면 `또렷하게 확인된 대사 없음` |

`반응 요약`을 인용문으로 표시하지 않는다. 모델명, 점수, 신호 가중치, 스키마, 파이프라인 단계는 요약에 넣지 않는다.

### 요청 시 표시

- 앞 맥락과 뒤 맥락 원문
- 전체 대사 목록과 시간
- 대표 화면 네 장
- 등장인물과 이름 근거
- 채팅 반응
- AI가 확인하지 못한 점

### 숨김

- `빠른 탐색 근거`, `전체 흐름 판정` 같은 내부 처리 명칭
- provider/model/revision/coverage/settlement 용어
- 동일 의미의 중복 문장

## 4. Keep / Delete / Merge / Move / Reveal

### Keep

- 좌측 도구 레일, 방송 제목, 후보 위치 스트립
- 요약/근거 탭, 키보드 단축키
- 사용/빼기/되돌리기, 시작·끝 다듬기
- 대표 화면, 실제 대사, 등장인물

### Delete

- 1280×720 강제 상한
- 근거 위에 떠다니는 340px 플레이어 카드
- 요약 화면의 내부 파이프라인 문구
- `reactionSummaryKo`를 대사로 표시하는 매핑

### Merge

- 사건·반응·추천 이유를 한 문단으로 합치지 않고, 하나의 `편집 판단 요약` 모듈 안에서 세 질문으로 정돈한다.
- 정점·대사·대표 화면을 하나의 시간축으로 유지한다.

### Move

- 전체 앞뒤 맥락, 인물 근거, 불확실성은 근거 탭으로 이동한다.
- 근거 플레이어는 팝업에서 근거 작업면 오른쪽 고정 영역으로 이동한다.
- 사용/빼기 버튼은 두 탭에서 같은 위치에 고정한다.

### Reveal on demand

- 근거 탭의 `맥락 더 보기`, `인물 근거`, `확인하지 못한 점`을 접어서 시작한다.
- 선택한 대사·화면·맥락 항목만 활성색을 주고 플레이어를 해당 시점으로 이동한다.

## 5. 텍스트 와이어프레임

### 안 A — 화면별 작업면 최적화 (권장)

```text
┌도구┬ 방송 제목 · 후보 진행 · 후보 위치 스트립 ──────────────────────┐
│레일│                                                            │
│    ├──────────── 요약 탭 ────────────┬──── 편집 판단 요약 ───────┤
│    │                                 │ 무슨 일이 있었나          │
│    │        큰 16:9 플레이어         │ 어떻게 반응했나           │
│    │                                 │ 왜 클립인가               │
│    ├──── 재생바 · 시작/끝 다듬기 ────┤ 핵심 대사 · 맥락 한 줄    │
│    └──────────── 사용 / 빼기 ─────────┴───────────────────────────┘

┌도구┬ 방송 제목 · 후보 진행 · 후보 위치 스트립 ──────────────────────┐
│레일│                                                            │
│    ├──────────── 근거 작업영역 68% ──────┬─ 고정 플레이어 32% ───┤
│    │ 대표 화면·대사·정점 시간축          │ 16:9 영상               │
│    │ 확인 대사 목록                       │ 현재 시각·재생바         │
│    │ 앞뒤 맥락 / 인물 / 불확실성          │ 사용 / 빼기             │
│    └───────────────────────────────────────┴───────────────────────┘
```

장점: 요약에서는 영상을 크게 보고, 근거에서는 시간축과 대사에 더 많은 폭을 준다. 플레이어는 항상 같은 화면 안에 있어 근거 선택 직후 위치를 잃지 않는다.

### 안 B — 두 탭 모두 영상을 왼쪽에 고정

```text
┌도구┬──────── 플레이어 58% ────────┬──── 요약/근거 42% ──────────┐
│레일│ 영상 · 재생바 · 다듬기       │ 선택한 탭의 모든 정보       │
│    │ 사용 / 빼기                  │ 세로 스크롤                 │
└────┴───────────────────────────────┴──────────────────────────────┘
```

장점은 탭 전환 때 영상 위치가 변하지 않는다는 점이다. 단점은 근거 탭의 대표 화면 시간축과 긴 대사가 42% 열에 갇혀, 큰 화면에서도 다시 좁은 문서가 된다는 점이다.

## 6. 권장 해상도 규칙

### 1280×720

- 바깥 여백 12px, 상단 도구줄 52px, 작업면은 남은 높이를 모두 사용한다.
- 요약 56:44, 근거 62:38.
- 내부 간격 12~16px, 버튼 최소 높이 38px.
- 문서 자체의 가로·세로 스크롤을 만들지 않고, 긴 근거 목록만 내부 스크롤한다.

### 1920×1080

- 바깥 여백 20px, 작업면 폭은 약 1880px.
- 요약 62:38, 근거 68:32.
- 16:9 플레이어를 약 960~1100px 폭으로 확보한다.

### 2560×1440

- 바깥 여백 24~40px, 작업면 최대 폭 2320px.
- 남는 폭은 영상과 근거 시간축에 우선 배분하고, 문장 행 길이는 별도로 제한한다.
- 작업면은 남은 세로 높이를 사용하되 단일 문단을 늘려 빈 공간을 채우지 않는다.

## 7. 상태·상호작용·모션

- 후보 전환: 재생 정지 → 새 후보 시작점 이동 → 선택 근거 해제 → 요약 탭. 소리는 자동 재생하지 않는다.
- 요약→근거: 같은 작업면 안의 본문만 교체한다. 근거 플레이어는 즉시 보이되 정지 상태다.
- 근거 선택: 항목 강조 → 해당 시점 seek. 사용자가 재생을 누르기 전에는 소리가 나지 않는다.
- `Space`: 현재 보이는 플레이어 재생/정지.
- `Q`: 요약/근거 전환. `J/K` 또는 위/아래: 근거 항목 이동. 좌/우: 후보 이동.
- 탭 전환은 160~200ms의 짧은 페이드/수평 이동만 사용한다. 후보 전환은 내용 페이드만 사용한다.
- `prefers-reduced-motion`에서는 이동·확대 없이 100ms 이하 페이드만 둔다.

## 8. 교체 범위

### 컴포넌트

- `ReviewCandidate`: 사건, 반응, 추천 이유, 실제 대사, 요약용 맥락을 역할별 필드로 분리
- `reviewSurfaceModel.ts`: `whyGoodClipKo`를 실제 용도에 연결하고 실제 cue만 인용
- `preparedReviewProjection.ts`: 네 문장을 합치는 `joinedDistinctText` 제거, 요약용 필드와 상세 근거 분리
- `ReviewSurface.tsx`: 근거 탭을 좌측 근거 작업면 + 우측 고정 플레이어로 교체
- `ReviewStage.tsx`, `PreparedReviewExperience.tsx`, `App.tsx`: 떠다니는 플레이어 카드 상태 제거 또는 고정 플레이어 상태로 단순화

### CSS

- `.rvw`의 `max-width: 1280px`, `height: min(74vh, 720px)` 삭제
- `.prv`를 `toolbar + minmax(0, 1fr)`의 2행 전체 높이 작업면으로 전환
- `.rvw-pcard`와 카드 진입 애니메이션 삭제
- 해상도별 레이아웃과 문장 행 길이 제한 추가

## 9. 브라우저 완료 조건

1. 1280×720, 1920×1080, 2560×1440에서 작업면이 뷰포트를 합리적으로 사용한다.
2. 추가 프로젝트 기준인 1024×768, 1440×900, 1600×900에서도 가로 넘침이 없다.
3. 요약은 사건·반응·클립 이유·실제 대사를 5초 안에 구별할 수 있다.
4. 근거 탭 진입 즉시 고정 플레이어가 보인다.
5. 후보를 바꾼 뒤에도 다른 근거를 눌러 플레이어가 항상 해당 시점으로 이동한다.
6. 근거 선택만으로 소리가 자동 재생되지 않는다.
7. 긴 한국어 제목과 최대 길이 데이터에서도 주 작업 버튼이 밀려나지 않는다.
8. 빈 대사·빈 맥락·빈 인물·빈 프레임 상태를 거짓 정보 없이 표시한다.
9. 키보드 전 동작과 포커스 표시가 유지된다.
10. 감소된 모션 설정에서 확대·슬라이드가 제거된다.

## 10. 권고

**안 A를 채택한다.** 같은 탭 껍데기를 유지하되, 요약과 근거가 서로 다른 편집 질문에 맞는 공간 배분을 갖게 한다. 기존 선정 로직과 저장 형식은 건드리지 않고 표시 어댑터와 검토 작업면만 교체한다.
