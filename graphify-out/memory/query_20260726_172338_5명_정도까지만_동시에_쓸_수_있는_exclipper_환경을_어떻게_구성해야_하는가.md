# Q: 5명 정도까지만 동시에 쓸 수 있는 ExClipper 환경을 어떻게 구성해야 하는가

## Answer

Expanded from original query via vocab: [transcript, transcription, worker, request, gate, rate, limit, concurrency, queue, session, provider, proxy]. Current browser worker creates per-tab AdaptiveConcurrency and RequestStartGate, raw WAV is sent by broadcastTranscriptQwenClient, and aiProxy.worker reads the body before local rate checks; any request error becomes a permanent transcription-failed gap. For a maximum of five active users, use one global AiQuotaCoordinator Durable Object keyed by a fixed name, with a shared five-participant admission registry and separate model-pool schedulers. Use stable installation clientId plus runId, fixed-schema small lease requests, fair work-conserving round robin, global ASR 700ms start spacing, max six ASR in-flight attempts, single-use short-lived lease tokens, and provider-429 backoff/requeue. Validate and consume the lease before the Worker reads WAV bytes; keep audio/frames/transcripts out of Durable Object storage. Bind every actual upstream attempt including fallback to a distinct permit. A sixth participant is not queued durably: return bounded capacity-full with Retry-After. Integration points are App currentAnalysisRunId, broadcastTranscriptWorkerClient request identity, broadcastTranscript.worker before requestBroadcastTranscriptChunkBinary, broadcastTranscriptQwenClient X-ExClipper-AI-Lease header, aiProxy.worker before body reads and around each provider attempt, plus wrangler Durable Object binding/migration.
