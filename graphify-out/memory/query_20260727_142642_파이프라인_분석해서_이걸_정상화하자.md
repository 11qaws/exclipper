# Q: 파이프라인 분석해서 이걸 정상화하자

## Answer

후보 맥락 크기는 실패 조건이 아니라 provider 호출 전의 결정론적 정규화 단계가 되었다. 전체 세션 자료는 보존하고 후보 전용 맥락만 UTF-8 48KiB로 구성하며, 후보 대사를 우선 보존하고 줄인 중간에는 명시적인 bilingual omission marker를 남긴다. provider prompt와 verification receipt는 동일한 canonical packet을 사용한다. 정상 최대 한국어·영어 입력도 80KiB prompt와 100k TPM 경계 안에서 실제 provider 실행까지 통과한다. 최종 후보는 whole-context, 네 화면, 오디오, 대사, insight, model, thumbnail, exact receipt가 IndexedDB write/readback에서 일치한 경우만 발행되며 저장 실패는 API 재호출 없이 저장만 재시도한다. 17개 whole-context cohort와 12개 detail cohort를 분리하고 후보별 실패를 격리했으며, gap 없는 정상 0개는 completedEmpty로 종료한다.

## Outcome

- Signal: corrected
- Correction: 이전의 80KiB 초과 후보 사전 중단 정책은 사용자 요구와 맞지 않았다. 합법적인 protocol 최대 입력을 사전 중단하지 않고 canonical 48KiB packet으로 provider까지 진행하도록 수정했다.
